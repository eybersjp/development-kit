# Architecture Invariants

These invariants must hold for the framework to function as designed. Any change that breaks one is an architecture regression.

## Lifecycle Invariants

1. **Stage order is fixed**: UNDERSTAND → DEFINE → DESIGN → PLAN → IMPLEMENT → VERIFY → REVIEW → SIMPLIFY → COMPLETE. No skipping, no reordering.
2. **Implementation is preceded by definition**: `/dk-build` cannot start without an approved spec/design/plan.
3. **Tasks are sequential**: the next task never starts while the current task has unresolved failures.
4. **Review order is fixed**: specification compliance → code quality → conditional reviews → simplicity.

## Agent Invariants

5. **The conductor never implements code itself.**
6. **Every implementation task uses a fresh sub-agent.**
7. **Specialists never spawn each other** — all orchestration flows through the conductor.

## Content Invariants

8. **Canonical is authoritative**: contributors edit `agents/`, `skills/`, `commands/`, `hooks/`, `templates/`, `evals/`, `scripts/` only; mirror copies are never edited directly.
9. **Manifest is generated**: `plugin.json` is regenerated by `sync-plugin.mjs`, never hand-edited.
10. **Canonical and mirror are one component** — never double-counted in docs or validation.

## Quality Invariants

11. **Spec compliance is verified before code quality** — "did we build the right thing" precedes "did we build it well".
12. **Completion requires fresh evidence** — never the implementer's word alone.
13. **Simplicity never removes**: security protections, input validation, error handling, accessibility, data integrity protections, or tests (Ponytail exclusions).

## Packaging Invariants

14. **Installer never overwrites user files without `--force`** (AGENTS.md, README.md, existing skills, package.json).
15. **Installer writes plain copies only** — no symlinks/junctions.
16. **`--dry-run` performs no writes.**

## Validation Invariants

17. **All three validators must pass before release** (`validate`, `doctor`, `docs:validate` per the documented release gates — CI currently enforces `validate` + `doctor`).
18. **Version tags must match `package.json` version** (enforced by the publish workflow).
