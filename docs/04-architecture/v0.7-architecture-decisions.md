# Planned v0.7 Architecture Decisions

> Status: Approved and implemented in Development Kit v0.7.0.

## V07-AD-01: DK Intelligence is integrated into Development Kit

- **Decision:** DK Memory, Knowledge, Code Intelligence, Context Assembly, provenance, and staleness form a built-in DK Intelligence layer.
- **Consequence:** Users do not install a separate memory application to obtain baseline functionality.

## V07-AD-02: DK Control Center is a DK interface, not a standalone product

- **Decision:** The first Control Center is a local browser UI served by the Development Kit runtime and shipped with the same Development Kit installation.
- **Consequence:** No Electron/desktop installer is required for v0.7. Future IDE panels reuse the Runtime API.

## V07-AD-03: Automatically open Control Center is configurable and defaults Off

- **Decision:** `Automatically open Control Center [On / Off]` is a first-class persisted setting with default `Off`.
- **Precedence:** project override -> global/user preference -> default Off.
- **Consequence:** When enabled, auto-open occurs only for healthy interactive runtimes and is suppressed in CI/headless/tests; duplicate launches are suppressed. Manual opening remains available regardless of the setting.

## V07-AD-04: Autopilot state remains separate from memory

- **Decision:** Existing Autopilot immutable state remains authoritative for workflow progress. DK Memory does not replace it.
- **Consequence:** Memory failure cannot silently rewrite or advance lifecycle state.

## V07-AD-05: DK Local Memory is the required default provider

- **Decision:** v0.7 baseline memory works locally without Docker, a cloud account, or an external memory service.
- **Consequence:** Advanced providers may improve capability but cannot become release prerequisites.

## V07-AD-06: TencentDB Agent Memory is an optional adapter

- **Decision:** TencentDB Agent Memory may provide Chat Memory, Skill, Wiki, and CodeGraph capabilities through DK provider interfaces.
- **Consequence:** Development Kit does not require Tencent's proxy, Docker stack, Node 22 runtime, or Tencent-specific infrastructure for core operation.

## V07-AD-07: Memory can inform but never authorize

- **Decision:** A remembered approval, preference, historical action, or inferred tendency can never satisfy a current DK consequential-action approval gate.
- **Consequence:** The existing policy/approval engine remains the sole authority for gated actions across CLI, agents, and Control Center.

## V07-AD-08: Memory authority and confidence are separate

- **Decision:** Records carry explicit authority classes such as `user-approved`, `repository-verified`, `system-verified`, `external-verified`, `inferred`, and `imported-untrusted`, independently of confidence.
- **Consequence:** High-confidence inference cannot masquerade as user approval.

## V07-AD-09: Project isolation happens before retrieval ranking

- **Decision:** Project scope is a hard partition/filter, not merely a ranking signal.
- **Consequence:** Similarity search cannot leak Project A memory into Project B by scoring it highly.

## V07-AD-10: Runtime API is the presentation boundary

- **Decision:** DK Control Center and future IDE-native interfaces consume a versioned local Runtime API rather than importing persistence internals.
- **Consequence:** One authoritative state/intelligence layer can support multiple interfaces.

## V07-AD-11: Control Center binds to loopback by default

- **Decision:** v0.7 Control Center is local-only by default, using an automatically selected loopback port.
- **Consequence:** Remote/LAN access is outside the baseline and requires a later authentication/transport-security design.

## V07-AD-12: Localhost is not an authentication boundary

- **Decision:** Browser writes require runtime session/capability protection and cross-origin/CSRF controls.
- **Consequence:** A malicious webpage cannot modify DK state merely because the Runtime API is on `127.0.0.1`.

## V07-AD-13: Provider detection never installs

- **Decision:** Providers may be detected and, when already installed/configured/permitted, automatically activated. Detection/activation must not silently install missing software.
- **Consequence:** Existing DK SYSTEM-class approval rules remain intact.

## V07-AD-14: Governance precedes semantic sophistication

- **Decision:** v0.7 first proves typed records, provenance, authority, staleness, scope isolation, deterministic retrieval, and correction workflows before requiring vector/embedding storage.
- **Consequence:** Semantic retrieval may be added behind the provider/storage contract when benchmarks justify it without destabilising the baseline.

## V07-AD-15: Planned architecture is not shipped documentation

- **Decision:** v0.7 specification documents remain explicitly marked planned until implementation passes release validation.
- **Consequence:** README/current-release claims must not advertise these features as available before verification.
