# Documentation Style Guide

## Principles

1. **Clear, Professional Tone**: Technical, unambiguous, direct language without marketing puffery or fluff.
2. **Standard Markdown**: GitHub Flavored Markdown with syntax highlighting and explicit language tags (`bash`, `javascript`, `json`, `mermaid`).
3. **Relative File Links**: Use relative Markdown links. Never use absolute local file system links.
4. **Mermaid Formatting**: Always enclose node labels in quotes when they contain special characters.
5. **Forbidden Content**: Zero uncompleted placeholder text, zero fake contact details, zero invented security reporting addresses.
6. **Command References**: All command pages must document syntax, inputs, outputs, invocation boundaries, and realistic usage examples.
