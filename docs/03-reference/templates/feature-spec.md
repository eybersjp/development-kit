# feature-spec

**Source**: `templates/feature-spec.md` · **Frontmatter**: `name: feature-specification`

## Intended Lifecycle Stage

DEFINE.

## Intended User / Agent

specification-agent (output of `/dk-spec`).

## Purpose

Concise feature specification: problem, users, expected behaviour, scope, exclusions, acceptance criteria, constraints, and risks — behaviour, not implementation.

## Required Sections

Problem · Intended Users · Expected Behaviour · Scope · Exclusions · Acceptance Criteria · Constraints · Risks

## Optional Sections

None.

## How the Template Is Selected

Standard artifact level (most features); selected by adaptive-artifact-planning.

## How It Should Be Completed

- Expected behaviour in observable terms
- Exclusions explicit
- Acceptance criteria testable (see acceptance-criteria-writing)

## Validation Expectations

- No vague acceptance criteria ("fast", "easy", "graceful")
- Exclusions present (even if "none")
